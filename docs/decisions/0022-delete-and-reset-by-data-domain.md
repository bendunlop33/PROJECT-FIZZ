# 0022: Delete my data and Reset coaching knowledge as database file swaps

**Status:** Proposed, 2026-10-11 (developer); revised the same day after review `docs/reviews/your-data.md`. It now follows the spec (§4.5, check 30, check 31a); the earlier divergences are withdrawn. One scope question for Ben remains (Export, below). Built and tested on Linux (real SQLite through the node driver and the expo-sqlite stand-in); not yet run on the iPhone.

## Context
data-import-export §2.6, §2.7, §3.6 and §4.5 (CLAUDE.md rule 10) ask for `Export: My data / Coaching knowledge only`, `Delete my data (keep coaching knowledge)` and `Reset coaching knowledge`, atomic and resumable after a force-close. The schema's append-only triggers forbid deleting sessions, sets, audits, coach records, memories and playbook candidates inside SQLite (ADR 0005: "deleting data is deleting database files"). Dropping the triggers would need a migration and would weaken the history guarantees for every other write.

## Decision
- **Every table is assigned to a domain** in `packages/persistence/src/data-domains.ts`. `exercises` is split by `owner_id` (no owner: Coaching knowledge; an owner: Your data, the same rule as the restore preview). A test compares the list with `sqlite_master`, so a new table fails until it is classified.
- **Delete** builds a new database file with only the Coaching-knowledge rows, integrity-checks it, and switches the `fizz-meta.db` pointer in one transaction (the restore mechanism). A force-close before the switch leaves all of Ben's data; after it, none. A marker (`data-ops.json`) is written just before the switch and records when the switch happened, so a resume finishes the clean-up but never swaps again (that would delete anything logged since). The clean-up, in order, each step repeatable: the old file and the rollback generation (and the last-restore record); rest alerts; **every backup file on this phone** and the backup record (`backup-state.json` started again), then one coaching-knowledge-only backup (`after_delete`); the Your-data files outside SQLite (`coach-connection.json`, `device-prefs.json`, crash notes, damaged copies kept aside, the capability-probe database); the ChatGPT sign-in (removed from the phone first, then revoked online, bounded at 10 s, offline is fine) and every Keychain item by key. No backup of Ben's data is made on the phone; the safety net is `Save a copy to Files first`, listed first with `No copy off this phone. Deleting removes the backups on this phone too.` when there is no copy in Files (§3.6).
- **A delete that can't finish at launch** shows `Deleting your data didn't finish`. If the switch never happened, the marker is cleared and the screen says `Nothing was deleted` (Continue opens the app as it was). If it did, the screen says `Your data is deleted. <step> didn't finish.` with `Try again`, and `Continue`, which clears the marker and records the step as unfinished, so the app opens at first run and a later launch never retries over new data.
- **Reset** builds a new file with every Your-data row, the knowledge exercises Ben's records use, and the bundled starter list. It switches in one transaction and keeps the old file as the rollback generation, recorded as `reset`. **`Undo last reset`** is offered on Data & backup and in the done alert; undoing records `undo_reset`, and undoing that puts the reset back. This needed meta-database migration 3 (the one-row `database_slots` table is rebuilt to widen the `switch_reason` CHECK). Reset backs up on the phone first (`before_reset`; it changes no personal data) and never touches credentials.
- Both are confirmed against a **stamp** of the current data (rule 5, the restore preview's stamp) and are idempotent by **op ID** (the ledger remembers the last 20). A damaged ledger is kept aside and started again once Ben confirms Delete or Reset; at launch it is left alone.
- **Export** writes one domain as JSON (`format: 'fizz-export'`, JSON columns opened) through the Files folder picker, then reads it back. With nothing in the chosen domain, Export is disabled and shows `Nothing to export`.
- No training-schema migration.

## For Ben
- **Export is JSON only in this milestone.** CSV, FitNotes 2 CSV, date ranges, warm-up toggle and the share sheet (§2.6, §4.4) aren't built; the folder picker is used instead. Proposed as a follow-up slice; accept JSON-only for now or ask for it before merge.

## Consequences
- Delete and Reset copy the whole database once (about 1.2 MB per 300 workouts, ADR 0005). Time on the phone is to be measured.
- Custom exercises (an owner) are deleted with Your data and untouched by Reset. Open decision B12 would make them Coaching knowledge; this is a one-line change in `domainOf`.
- **Not built:** CSV and FitNotes 2 CSV export, export ranges, the iOS share sheet (export uses the folder picker), guide files and the guide index (not in the app yet), saved import layouts (no table yet; the import's `exercise_aliases` are Your data and deleted), cancelling AlarmKit alarms and Live Activities and stopping audio (not wired yet; only the rest notification is cancelled; add them to the clean-up when they land), releasing a backup-folder bookmark (not stored yet), a write gate while the manager switches files (review N6: a write that reaches the old file between the snapshot and the switch is lost, as with restore; the cover is modal).
- **Device checks:** Keychain items gone after Delete (including after a reinstall), `deleteDatabaseAsync` removes `-wal`/`-shm` for the old files, `Documents/backups` empty except the knowledge-only backup, the probe database gone, a force-close during the cover finishes on relaunch, and the folder-picker export to iCloud Drive.
